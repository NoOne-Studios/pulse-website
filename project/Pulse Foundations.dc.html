Foundation layer · v1 · engineering handoff
Pulse — Design Tokens
Every token below is semantic: it names a job, not a colour. Engineering consumes the names; the values are ours to change. Literal ramp values appear once, in the primitive layer, and nothing in the product references them directly.
How to read this
Two layers
Primitives (--blue-600) are private. Semantic tokens (--color-action-primary) are the public API. A component referencing a primitive is a bug.
Theming
Only semantic tokens are re-declared under [data-theme="dark"]. Same names, different values — no component branches on theme.
Script-aware type
Type tokens come in Latin and Tamil pairs where the scripts genuinely need to differ. Everything else is shared, so there is one scale, not two.
Naming
--{category}-{role}-{variant}-{state}. Categories: color, font, space, radius, elevation, border, motion, size.
01 · Colour — surfaces and text

White is the base surface and cards sit on it flush, separated by border rather than shadow. Sunken is the only tinted ground and it is used for insets inside cards, never for the page. Blue is the action colour and appears nowhere as decoration.

03 · Type scale

Latin runs Hind, Tamil runs Hind Madurai — same superfamily, so weights and colour match without tuning. Three rules where the scripts diverge, applied throughout:

  • Tamil line-height is +0.15 over Latin at every step — the script's ascenders and vowel signs collide at Latin leading.
  • Tamil letter-spacing is always 0. Never track Tamil, including in uppercase-style labels; the shaping breaks.
  • Tamil display sizes step down −2px from Latin so the two scripts have matching optical weight in a bilingual lockup.

05 · Iconography

24px grid, 2px live-area inset, 1.75px stroke, round caps and round joins — the same drawing rules as the pulse mark, so the icon set and the logo look drawn by one hand. Outline only; no filled icons, no two-tone, no colour inside an icon. Icons inherit currentColor without exception.

Below 20px the stroke steps to 2px and interior detail is dropped rather than scaled. An icon never appears without a text label in a primary action — this audience does not read icons alone.

06 · Motion

Motion in this product is confirmation, never celebration. People book here because someone is unwell. A bouncing success animation on a confirmed hospital-grade visit is tonally wrong, and it delays the information. Nothing overshoots, nothing springs, nothing scales above 1.0, and no confetti, ever — including on first booking, referral, and payment success.

--motion-duration-instant · 0ms
Selection, checkbox, tab switch. State the user caused directly is immediate.
--motion-duration-fast · 120ms
Hover, focus ring, button press. Colour and opacity only.
--motion-duration-base · 180ms
Accordion, inline expand, toast in. The default.
--motion-duration-slow · 240ms
Bottom sheet, modal, screen transition. The ceiling — nothing is slower.
--motion-ease-standard
cubic-bezier(.2, 0, 0, 1)
Everything that moves on screen. Decelerating, no overshoot.
--motion-ease-exit
cubic-bezier(.4, 0, 1, 1)
Things leaving. Accelerate out; don't linger.
--motion-ease-linear
linear
Progress and the en-route pulse only. Never for layout.
No spring tokens exist
There is no bounce, elastic, or back easing in this system — omitted so it can't be reached for.
Reduced motion — prefers-reduced-motion: reduce
  • All durations collapse to 0ms via the token, not via a blanket * { animation: none } — components keep working, they just arrive instantly.
  • Position and scale transitions become cross-fades at 0ms; sheets appear in place rather than sliding.
  • The en-route pulse indicator stops animating and becomes a static filled glyph — the information is in the glyph and label, never in the animation.
  • Loading skeletons stop shimmering and render as flat surfaces; spinners become a static determinate bar or a text status.
07 · Accessibility
Contrast
  • Body text ≥ 7:1 (AAA), not 4.5. Daylight on a cheap LCD eats the difference.
  • Any text below 15px must clear 7:1 — no exceptions for captions.
  • Non-text (icons, borders, focus ring) ≥ 3:1 against its neighbour.
  • Disabled controls are exempt from contrast but must never be the only affordance.
Targets
  • --size-target-min: 48px. Not 44 — the older end of the audience is the design point.
  • Minimum 8px between adjacent targets.
  • A visually smaller control keeps a 48px hit area via padding or a pseudo-element.
  • Destructive actions (cancel a visit) are never adjacent to a confirm.
Focus
Focused
Focused
  • 2px ring, 2px offset, --color-border-focus. Same ring on every control.
  • Never removed — :focus-visible only, so it doesn't fire on touch.
  • Ring sits outside the element so it survives on coloured surfaces.

Assumptions to confirm before engineering builds on this
  • Three service lines are drawn as home nursing, lab sample collection, and physiotherapy. If the real lineup differs, the icons change but the rules don't.
  • All Tamil strings remain placeholder, including the specimen sentences here. Line-height and size ratios were set for the script generally and should be re-checked against real copy.
  • Contrast ratios are calculated, not measured. Worth one pass on a low-cost Android panel outdoors before engineering locks the ramp.
  • Hind / Hind Madurai are Google-hosted. If the app must work offline-first or on very slow connections, we should self-host and subset — that decision affects the type tokens' fallback stack.
